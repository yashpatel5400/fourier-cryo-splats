update(complete=True, ...)` call precedes the numerical-failure `AssertionError`, so the except branch adds an `error` key to a record that already says complete. Downstream code that filters on the complete flag would include a numerically failed audit. No archived case triggered this. Fix: set `complete=False` when `numerical_failure` is true, or make the summary script filter on both keys.

**B4. Block-scale consistency is checked through a single scalar.** Severity: low. Location: `scripts/audit_uq_joint_bias.py`, the `assert_allclose(scale_sum, fit['initial_group_scale_sum'])` line, and the same check in `scripts/probe_uq_pose_exchange.py`. The joint bound, the cross vector, and the spectral certificate all depend on the full vector of 2n denominators. Agreement of the sum to 1e-8 is strong evidence that the same inputs and code were used, but it is not a proof that the denominators match. Fix: persist `group_scales` in the fit npz, hash it, and assert the full vector in both scripts.

**B5. The cross-term pad and the Gaussian moments are untested in the archive regime.** Severity: low. Location: `tests/test_uq_joint_bias.py`; `gaussian_fourier_moments` in `src/fourier_splats/uq_joint_bias.py`. The moment test uses width 0.19 and k ~ N(0,1), so the imaginary part of the complex normal CDF argument is about 1.2. The archive uses width 0.07 and |k| up to 5, so the argument reaches about 2.2 and the difference of two CDF values is a cancellation between quantities of size roughly e^{2.4}. The isfinite check does not catch loss of relative accuracy. Separately, no test checks the certified inequality |cross_32 − cross_exact| ≤ pad; the tests only confirm the target moments and that `target_pose_cross` matches `rmatvec` at one quadrature order. The sharp cubic test uses angle 0.08 rad and |k| about 1, whereas the archive uses 0.035 rad and |k| up to 5, and it never points R^T(k×ω) along the maximizing diagonal direction. Fix: add a moment test at width 0.07 and |k| = 5 against a 200-node one-dimensional rule; add a test comparing the order-32 cross vector against an order-96 direct-backend evaluation and asserting the difference is below `quadrature_norm_pad`; add a sharp-cubic case with the rotation axis chosen so that k×ω is along (1,1,1)/√3 at the archive angle.

**B6. The full-weight cut path with nonempty cuts has no isolated test.** Severity: low. Location: `solve_full_weight_cut_problem` in `src/fourier_splats/uq_pose_exchange.py`; `test_full_weight_projected_conic_dual_brackets_exact_unprojected_optimum`, which passes an empty cut array. The restricted-weight sibling is tested with cuts, and the code is nearly identical, so the risk is small. Fix: port the exact-spectral-matrix fixture from `tests/test_uq_pose_exchange.py` to the full-weight function with a projection of rank below m+1, and assert lower ≤ exact ≤ upper plus global validity of `pose_support` on random weights.

**B7. Several certificates now exist for the same weights.** Severity: low. Location: `--certificate-seed` in `scripts/probe_uq_pose_exchange.py`; the conic-duals fit, the six-round trial, and the adaptive run all certify the same input weights with different seeds. Each certificate is valid at failure probability 1e-6, and the alpha accounting charges one such event. Choosing the smallest of several certificates for identical weights would require a union bound. With three certificates the extra 2e-6 is negligible against alpha, so this is a discipline point rather than an invalid bound. Fix: state the rule that a reported width uses the certificate of the run that produced it, and record the seed in any summary row.

**B8. Reporting is conditional on non-vacuous original intervals.** Severity: low. Location: `scripts/audit_uq_joint_bias.py`, the `raise ValueError('Reference recentering needed for fallback case')` branch; `results/uncertainty/development/joint-bias-summary/summary.json`, which reports six completed cases with no attempted count. The six-row summary is fine as a development record but must not be read as the set of all fits. Fix: list attempted fits and their failure reasons in the summary.

**B9. Gap reporting for the joint bound needs its own bracket.** Severity: informational. Location: `existing_feasible_over_new_upper` in the audit script; `relative_sum_gap` in the probe. No current output compares the J lower bound to the joint-audited value, which is correct. If a future summary wants a tightness measure for the joint bound, the appropriate bracket is [max feasible bias, joint upper], and the ratio 0.566 already gives that for the archive case. The J dual lower bound is not a lower bound on the joint expression and should never be placed beside it.
